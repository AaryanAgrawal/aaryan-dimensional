## DanHolonomic trajectory controller (branch `aaryan/g1-danholonomic`)

The ticket's own "DanHolonomic controller is the alternative to try" for Andrew's basic P follower.
Swaps `BasicPathFollower` for the `DanLocalPlanner` + `DanHolonomicTC` pair, copying the wiring from
the Go2 analogue `unitree_go2_mls_htc.py`.

```
MLSPlannerNative.path --(planner_path)--> DanLocalPlanner --(path)--> DanHolonomicTC --> MovementManager
                                              ^ odom                      ^ odom
                                         GoalRelay.start_pose (ground-projected PoseStamped)
```

Holonomic means it tracks position and heading as independent objectives — the G1 can strafe, so it
does not have to face where it is going. `BasicPathFollower` couples them through `heading_gain`.
`DanLocalPlanner` resamples first because MLS paths follow voxel edges and the tracker would
otherwise chase corners.

New `g1_walk` run profile. `speed=0.4` and `max_yaw_rate=0.5` are the two numbers Andrew already
validated on this robot via `BasicPathFollower(speed=0.4, max_angular=0.5)`; the accels are halved
from Go2 `walk` as conservative biped bring-up values and are **not measured**. This matters because
`G1HighLevelDdsSdk` has no upper velocity clamp — only `_boost_above_deadzone`, which raises small
commands UP to a floor. The profile is the only cap.

Verified: ruff + mypy clean, 20 dannav tests pass, 105 blueprints valid, and on the robot the
blueprint constructs with 12 modules and all four remappings resolve. **Not yet driven** — no goal
has been clicked through this controller.
