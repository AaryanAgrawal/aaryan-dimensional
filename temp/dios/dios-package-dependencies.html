A Better Package Dependency System for DimOS

Today dimos run can react to a few missing Python imports, but it cannot determine all Python, system, native, or runtime dependencies for a blueprint. This MVP gives DIOS that information without creating a second package database.

Keep what already owns versions

  • Existing Python packages: pyproject.toml and uv.lock
  • Existing Rust crates: Cargo.toml and Cargo.lock
  • Existing C++ build dependencies: CMakeLists.txt
  • Existing Nix versions: flake.nix and flake.lock

Add beside each runnable module

fastlio/
├── module.py
├── cpp/CMakeLists.txt
└── dependencies.toml   ← NEW
schema = 1
module = "dimos.hardware.fastlio"

[system]
apt  = ["libeigen3-dev"]
brew = ["eigen"]
nix  = ["eigen"]

[requires]
ros = "humble"

The module name selects its matching Python extra in pyproject.toml.

How it works

module dependencies.toml
          ↓
DIOS combines + installs with uv / apt / brew / nix
          ↓
DIOS records observed versions locally
          ↓
dimos run checks readiness before starting

Runtime checks are read-only. If something is missing, DimOS prints the exact DIOS repair command instead of installing unexpectedly.

Enforcement

New A dependency is declared in the same PR that first uses it. Greptile flags omissions and CI validates the TOML. Manifests cannot contain arbitrary shell commands.

Review decision: should this be the dependency contract for every runnable DimOS module?
