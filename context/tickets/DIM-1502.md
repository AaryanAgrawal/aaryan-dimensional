## The startup hazard — CONFIRMED IN CODE, not a guess (2026-08-22)

`unitree_g1_sonic_wbc.py` real-hardware branch (the `else:`, lines ~180-190):

```
_backend      = G1WholeBodyConnection.blueprint(release_sport_mode=True)
_auto_arm     = False
_auto_dry_run = True
```

`G1WholeBodyConnection.start()` calls `_release_sport_mode()`, which loops
`MotionSwitcherClient.ReleaseMode()` until MotionSwitcher reports no active controller, then logs
"Sport mode released - low-level control active".

So at connect:

```
release_sport_mode=True  ->  Unitree's own balance controller is RELEASED
auto_arm=False           ->  the SONIC policy is NOT armed
auto_dry_run=True        ->  ...and is emitting nothing
                         =>  nothing holds the robot up until the operator arms it
```

**A standing G1 will drop at startup.** First hardware run goes on the gantry, or starts from a
seated/damped pose. Never from standing on the floor.

Other real-hardware settings: tick 100 Hz with `_decimation = 2` (50 Hz policy), ramp 10.0 s,
`_n_workers = 10`. Sim differs deliberately: `_auto_arm = True`, `_auto_dry_run = False`, 50 Hz tick.

## What it is

NVIDIA GEAR-SONIC v1.1 as a **ControlCoordinator task** (`g1_sonic_wbc_task`), not a standalone
stack. Whole-body torque control: walking, 27 locomotion modes, mocap clip playback, upper-body
teleop. Assets pull from LFS on first run (`data/sonic`, ~950 MB).

RPCs via `task_invoke("sonic_wbc", ...)`: `set_velocity_command`, `set_locomotion_mode`,
`play_motion_clip`, `set_upper_body` (17-dof), `set_vr_3point`, `set_base_height`,
`state_snapshot`, `arm` / `disarm` / `set_dry_run`. Also speaks SONIC's native ZMQ
(SUB :5556 / PUB :5557) behind `zmq_enabled`, as an optional ingest adapter.

Upper-body targets are encoder hints, not IK: the policy follows them while keeping balance.

Files: `g1_sonic_wbc_task.py` (771), `sonic_pipeline.py` (1210), `streamed_motion.py` (260),
`zmq_wire.py` (174), the blueprint (328), plus the LFS asset and a touch to `mujoco_sim_module.py`.

## Watch for

- Whole-body torque controller, same hazard class as groot-wbc. Gantry + e-stop for the first run.
- `arm` / `disarm` are the safe handles. `disarm()` is the stop — see [`../G1-ESTOP.md`](../G1-ESTOP.md).
- Same environment gotchas as DIM-1494: the LCM network fixes do not survive reboot
  (`ip link set lo multicast on`, `ip route replace 224.0.0.0/4 dev lo`), and the open3d static-TLS
  failure hits any stack decoding pointclouds on the Jetson (`LD_PRELOAD=.../libgomp.so.1`).
- LFS: always `GIT_LFS_SKIP_SMUDGE=1` on checkout, then pull the sonic asset deliberately.
