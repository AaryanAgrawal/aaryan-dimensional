## E-stop (branch `aaryan/g1-estop`, no Linear ticket yet)

Wired into this stack because kronknav has a MovementManager and no ControlCoordinator. Will be
spun out to feed `ControlCoordinator.set_estop` once it moves to the groot stack.

```
rt/lowstate (DDS, 500 Hz) -> [silent? fallen?] -> estop: Out[Bool] -> MovementManager gate
```

`dimos/robot/unitree/g1/g1_estop.py` + a 4-line gate in `movement_manager.py`. 259 lines added,
0 removed, 6 files.

Why DDS and not LCM: no LCM signal is common to both stacks. kronknav publishes no `Imu`; groot sim
publishes no `Odometry`. `rt/lowstate` is identical on both, and the pelvis IMU is gravity-referenced
so it needs no mount correction — which is also why the third copy of `diag(1,-1,-1)` could be deleted
rather than moved.

Why not the LIO pose: scan matching degrades during the very event being detected.

Hardware-verified 2026-08-21 on the real robot, bus otherwise idle:
- 45 deg shipped threshold, 8 s standing: 351 publishes at 44 Hz, zero false trips.
- Forced 1 deg threshold: tripped on real data (`tilt_deg=1.8`), latched, asserted `estop=True` on
  373/373 later cycles — the latch holds and a late subscriber still sees the stop.
- hg `imu_state.quaternion` order is **wxyz**, confirmed to 4.8e-11 against the same frame's `rpy`.
  Reading it as xyzw gives 178 deg on a healthy standing robot, i.e. an instant false trip.

Not yet done: trip has never been exercised through a running kronknav stack (only the detector in
isolation), and the groot tail (`G1GrootWBCTask.set_estop` -> the existing `disarm()`) is unwritten.

### What the branch sweep found (1,606 refs)

- Nothing in dimos consumes any hardware fault field. Motor `temperature`, motor `lost`,
  `bms_state.status`, `cell_vol`, `power_a`, `fan_frequency`, `wireless_remote` are all decoded and
  dropped. The only hardware value anywhere that gates behaviour is `foot_force`, on one Go2 branch.
- `ControlCoordinator.set_estop()` exists and fans out via `getattr(task, "set_estop")`, but only two
  arm tasks implement it — **no G1 task does, so on the G1 it is a no-op today**.
- `G1GrootWBCTask.disarm()` already exists, docstring: "Called either from an operator Disarm button
  or from safety watchdogs." The watchdog it was written for was never built.
- Measured-but-unusable as fault signals: `ddq` (exactly 0.0 across 6259 frames), `tau_est`
  (current-derived, ~0 while motors are disabled), `lost` (a go2 field, absent on hg).
- Not thresholded on purpose: motor `temperature` (33-45 C idle) and `vol` (51.0/51.5 V). No legged
  thermal or undervoltage limit exists anywhere in the repo, and inventing one from an idle sample
  would be a guess with a decimal point.
